# 持久化容量与保留策略候选

## 已核实的行为

M4 checkpoint.save以完整window/history/config/result的内容摘要命名，临时文件fsync后原子替换。online中的180秒历史裁剪只限制当前内存观测，不会删除已经落盘的旧检查点。每个新窗口通常产生一个新文件；不能把内存有界解释为磁盘有界。

SP-02 core.Journal.accept目前每次新观测都读取既有observations并反序列化，用于判断同scope的seq倒序。随记录增长，单条接收工作量可能线性上升，持续批次总工作量可能接近二次增长；这是静态复杂度风险，不是本轮已测吞吐结论。需优先在MQTT长时运行中量测入库/ACK延迟及队列积压，再单独优化。

## 本批工具及边界

scripts/audit_runtime_storage.py只读打开业务库和可选Journal，对数据库TEXT列中的JSON递归收集显式asset_refs/state_checkpoint_ref，统计检查点总量、已发现引用、缺失引用及未观察到引用文件。读取使用一致数据库事务，文件列表不与事务构成原子快照。相对/外部路径单列，文件名和JSON内容不输出到报告。

未观察到引用不等于可删：内存中的恢复状态、外部导出包、其他库、历史快照、非显式路径和仍在发布的工件均不在完整保护证明内。本工具永远输出deletion_authorized=false，不提供删除参数。

## 推荐保留模型（尚未实现）

1. 区分当前运行检查点、事件证据、冻结实验、显式导出/人工保留四类根。冻结实验与导出副本不能由运行时清理器删除。
2. 以明确的pin索引和来源版本记录保护引用，文件发布、pin登记和投影更新需证明中断下的一致性。数据库事务与文件系统不能简单假定原子。
3. 配额达到预警值时先报告降级及剩余空间；不得静默继续显示健康，也不得自动删除尚未确认的事件证据。
4. 第一版清理仅离线执行：停止写入、完整备份、计算候选、校验全部pin、隔离到同工作区回收目录并生成清单；审批与实际删除另批处理。本候选不授权清理现有目录。
5. 回收必须可恢复，启动恢复不能因旧绝对路径失效而伪造正常；只有超过明确保留期且复核无引用后才考虑最终删除。

## 验收矩阵

新增保留实现前覆盖：当前投影引用保护、开放/已关闭事件证据保护、已导出实验保护、跨boot恢复、磁盘空间不足、写入/清理中断、损坏pin索引、符号链接或路径越界、数据库备份恢复、重复执行幂等。验证不得用单纯glob删文件代替引用管理。

## MQTT长时量测任务

需要独立受控broker/subscriber/publisher/edge四进程，按真实1秒左右三源节奏发布，不压缩时间。记录Journal observations/attempts/rejected、业务消费游标及lag、各进程RSS、SQLite含WAL体积、检查点、PUBACK与持久ACK延迟。停报/重连/新boot用单独阶段标注，不能将故障期预期UNKNOWN计为正常连续输入失败。

本轮一小时运行只覆盖内置simulation，没有SP-02 Journal。已有270条MQTT恢复观测只能证明该短场景，不可写成一小时MQTT容量验收。
