# 前端优化第一阶段：公共框架与状态反馈

基于 main `611685d266c15cd493f2b2d3ab80568e67732f8f`，在独立工作区及分支 `feat/workbench-polish-20261119` 开发。

## 本轮交付

- `web/src/c-shell.css`：统一公共色彩、字号、间距、导航选中态、按钮尺寸、焦点样式和窄屏布局；保留现有绿色视觉风格。
- `web/src/c-connection.js`：独立计算未连接、等待响应、全部可用、部分失败和全部失败状态。凭据存在不再意味着接口可用；接口可用也不代表传感器新鲜或云回执成功。
- `web/src/c-main.jsx`：接入状态提示、最近查询完成时间和键盘跳转入口。查询完成时间明确区别于传感器观测时间。
- `web/src/c-navigation.jsx`：侧栏使用工作台标识；实际接口状态集中在公共连接区展示。
- `web/tests/c-connection.test.js`：五项状态语义回归检查。
- `web/tests/shell-acceptance.cjs`：浏览器验证等待响应、部分失败、全部失败、401、断开清理及键盘跳转。通过拦截只读查询构造失败，不调用业务写入接口。

4. 浏览器状态与键盘检查 7 项通过，页面脚本错误为零。
5. 人工查看修改后移动端总览和桌面事件详情截图，确认公共连接区、导航、卡片与操作按钮正常排布；其余截图保留供人工验收。

证据：`audit/frontend-stage1-20261121/before-final/`、`after/` 和 `shell-result.json`。

截图来自独立临时业务数据库：调用现有 Simulation 按秒生成 86 个模拟步骤，固定查询时钟，启动仅本地监听的 API，截图后关闭本轮拥有的服务进程。临时凭据仅用于该夹具。未连接实验数据库、MQTT broker 或云端，也未启动一小时实验；这些结果仅证明界面及状态交互，不能作为真实实物或长时可靠性验收。

浏览器脚本复跑需要自行启动隔离的本地业务服务，设置 `UI_BASE_URL`、`UI_TOKEN`，并提供 Playwright（可用 `PLAYWRIGHT_MODULE` 指向已安装模块）、浏览器路径 `CHROME_PATH` 和结果文件 `UI_RESULT`，然后运行 `node web/tests/shell-acceptance.cjs`。服务须能成功响应默认 demo01 的四项查询；脚本随后模拟部分失败、503 和 401。

## 后续阶段

第二阶段细化实时总览和数据可视化：信息层级、指标单位、时间范围、来源与新鲜度说明，以及空数据和接口异常呈现。

第三阶段细化事件确认与实验诊断：突出当前可执行操作、事件状态与时间线、诊断结论和证据入口，保持确认/关闭业务条件及请求意图语义。

最后进行完整人工验收，再决定合入主线；真实实验使用固定版本，前端开发与实验数据隔离。本轮未改变 B 算法、业务接口、数据库结构、云 worker 或 MQTT 测试策略。
