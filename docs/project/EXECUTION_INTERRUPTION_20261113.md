# 实验中断调查与独立运行修复

## 调查结论

原实验c253c93在11:54:36（北京时间）启动，最后样本12:44:30、elapsed=2992.828秒。其195个稳态样本均200，但没有result.json、没有正常服务关闭或Python异常堆栈，进程/端口均消失。因此只记INCOMPLETE，不算一小时通过。

执行环境更新器日志给出独立时间线（UTC加8为北京时间）：

- 04:43:39附近：scheduled更新选择0.168.0包。
- 04:43:40.644：restart_requested，shutdownGraceSeconds=60。
- 04:43:40.645：shutdown_requested。
- 04:44:40.684：shutdown_forced。
- 04:44:42.126：replacement process_spawned。

执行守护进程的PID文件/日志轮换也发生在12:44:41–45。中断同段System电源/重启事件及Application崩溃事件查询未返回相关记录；这只是未找到，不是所有潜在原因已排除。

可以确认执行环境发生了自动更新与强制重启，实验依附会话随后失效；这是中断的最直接、时间吻合的解释。没有逐PID终止审计，不能声称已取得观测器被具体kill调用终止的直接记录，也不把本次中断认定为项目业务崩溃。不修改执行环境自动更新设置。

## 修复

- scripts/start_endurance_task.ps1：注册当前用户、Limited权限、无周期触发的Windows计划任务并立即启动。执行pythonw避免弹窗；任务时限为实验时长加1800秒，使用新目录/端口，保存唯一任务名回执。由Task Scheduler托管，而不是Codex执行会话。
- scripts/supervise_endurance.py：独立监督子进程，10秒原子心跳，记录监督/子PID、子退出码、结果是否存在及最终状态；监督异常清理自有进程树。子返回非0或缺少结果时不写成completed。
- 监督器先将自身与未来子进程绑定Windows Job Object（KILL_ON_JOB_CLOSE），进程退出时操作系统清理其后代；避免强制停止计划任务留下服务。句柄保持到进程退出，不提前关闭来误杀监督器。
- 观测器增加progress.json阶段记录和60秒本地堆栈超时诊断；监督器总等待限制为请求时长加90秒，不让心跳掩盖无限卡住。堆栈仅本地保存，不输出变量或凭据。
- 观测器仍按原有API、采样覆盖、DB、进程退出和端口标准判定，不放宽TTL或删失败样本。
- 不写密码、传感原始内容或访问token到监督回执；stdout/stderr在本地监督日志。单独写临时文件并fsync/replace，降低部分写入风险。

这能隔离执行环境重启，不保证跨用户注销、系统重启、断电或主机故障继续运行。Interactive任务需要用户保持登录；已启用的keep-awake也不能阻止用户主动睡眠。没有实际强制重启开发工具来做破坏性验证。

## 验证

监督器原子回执/失败子进程测试与观测工具联合10项通过。第一次60秒独立任务完整退出、回执failed/child_exit_code=1，接口正常；因12秒启动采样空档超过5秒interval对应10秒门槛而FAIL，记录保留。已删除该已结束自有任务的注册，未删证据。

第二次90秒使用15秒采样但未写出样本，已受控停止；当时缺少阶段堆栈，无法事后确认卡点。增加阶段/堆栈与总等待限制后，新90秒任务PASS（92.250秒），四个稳态样本正常，子退出0、计划任务结果0、端口关闭；不将诊断性改动宣称为已证实修复该未知卡点。

强制停止原第二次任务后发现其8050端口有自有残留服务，核对PID、名称及创建时间后清理；Job Object修复后另起任务8053端口并明确Stop-ScheduledTask，验证端口关闭，Task Scheduler结果267014（被终止），无观测result.json，不伪造成功。测试任务注册均按各自唯一回执清理，证据保留。

最终51dde9f带Job Object的90秒正常完成验证另行归档。本轮任务均不依附命令会话，启动命令返回后仍持续采样；未通过重启真实开发工具来做破坏性验证。

最终验证实际92.438秒、7次采样、4个稳态样本全部正常，最大采样间隔16.875秒，小于15秒interval对应30秒覆盖门槛；数据库完整性ok、无重复OPEN、观测进程退出及端口8054关闭。监督器completed、child_exit_code=0、kill_on_supervisor_exit=true，Task Scheduler LastTaskResult=0。不能把90秒结果当作一小时通过。

清理时按已确认PID、进程名与创建时段保护其他程序；发现共享端口的非本实验进程后保持原状，未因端口相同终止无关进程。

## 运行方式

在已安装依赖的完整仓库中，用PowerShell执行以下模板（选择新目录、空闲端口、实际pythonw路径）：

```powershell
./scripts/start_endurance_task.ps1 -Directory '<新实验绝对目录>' -Pythonw '<应用环境>/Scripts/pythonw.exe' -Seconds 3600 -Interval 15 -Port 8051
```

状态分别查看 `<目录>.task.json`、`<目录>.supervisor.json`、`<目录>/samples.jsonl`、`<目录>/result.json`。只有监督completed、子退出0且观测PASS，才可按实际时长宣布通过。运行中不改该工作树的业务代码；其他开发使用独立worktree。结束后按回执唯一task_name清理自有计划任务注册，保留证据。
