# 零基础软件安装与复现手册（Windows）

2026-11-03。配合[S1–S3逐人操作卡](S1-S3_逐人操作卡.md)。先完成公共准备，再按A/B/C分支执行。不需要先接传感器或购买云服务器。本文覆盖已核对的健康服务、SP-02通信、B离线演示、SP-06事务原型；新出现的`spikes/C-business`不在本轮复现范围中，勿混用其端口与页面。

## 1. 软件与版本清单

下表为本工作区核对到的复现基线，不代表所有其他版本均不兼容。换版本必须重新记录并验证。以下操作面向Windows x64；ARM电脑先向组长确认，勿照选x64安装器。

|软件|本机基线|谁需要|用途与来源|
|---|---|---|---|
|Windows及PowerShell|使用Windows自带PowerShell，本次未固定系统构建号|全员|输入运行命令|
|Python|3.12.10，64位|全员|运行后端和原型；[官方发布页](https://www.python.org/downloads/release/python-31210/)|
|Node.js / npm|24.13.0 / 11.6.2|跑网页的成员|Node安装后附带npm；[官方版本目录](https://nodejs.org/dist/v24.13.0/)|
|Mosquitto|2.1.2，64位|A通信实验|本地MQTT中转；[官方下载安装页](https://mosquitto.org/download/)|
|Git|本机2.52.0.windows.1，不是脚本硬性要求|使用Git取代码的成员|记录代码版本；已有项目文件可先跳过；[官方Windows入口](https://git-scm.com/download/win)|
|编辑器|记事本即可；VS Code可选、不限定版本|全员|查看代码和JSON，不负责运行环境|
|浏览器|现有Edge/Chrome即可，未固定版本|跑网页的成员|打开本机网址|

Python包无需逐个下载安装：`requirements-app.lock.txt`固定FastAPI 0.162.0、Uvicorn 0.53.0、Pydantic 2.14.1、paho-mqtt 2.1.0、pytest 9.1.1等。前端由`web/package-lock.json`固定，主要是React 19.3.1、Vite 8.3.5、React插件6.1.2。不要复制别的项目的依赖清单。

### 安装时具体选择

1. Python：打开官方3.12.10页面，选择Windows installer (64-bit)，不要选embeddable压缩包。运行安装器，勾选“Add python.exe to PATH”；保留pip与Python Launcher组件，完成安装。若已有可用3.12.10，不重复安装。
2. Node：版本目录中选择`node-v24.13.0-x64.msi`，使用默认组件并安装npm；不需要额外安装编译工具来开始本轮演示。
3. Mosquitto：选择2.1.2的Windows x64安装器，记录安装位置。若安装器提供Windows服务选项，本轮使用手动启动，可不安装服务；若已装服务，不擅自停止已有服务，后文可用独立18885端口。
4. 软件装完后关闭旧终端，重新打开PowerShell，让新PATH生效。浏览器下载失败先记录错误，不从不明网盘换安装包。

## 2. 第一次打开项目和终端

“终端”是输入命令的窗口，“浏览器地址栏”是输入网址的位置，二者不要混用。

1. 用文件资源管理器打开组长发来的项目文件夹。根目录应直接包含`README.md`、`requirements-app.lock.txt`、`edge`、`spikes`、`web`；解压后可能还有一层同名目录。
2. 点击资源管理器地址栏，输入`powershell`，按Enter。窗口提示符应以当前项目路径结尾。
3. 如果用开始菜单打开PowerShell，需要先切目录。下面路径仅适用当前电脑，其他同学替换为自己的完整路径，保留引号：

```powershell
Set-Location -LiteralPath 'D:\高ice（大学版）\2026-2027 大二\10月华为ICT实践赛'
Get-Location
Test-Path .\requirements-app.lock.txt
```

最后应为True。False表示目录不对，先停止。命令块只复制内部命令，不复制三条反引号、提示符或输出。每次一行，按Enter，等待提示符返回再执行下一行；服务器长期占用窗口是正常的。

私有仓库由组长提供准确地址和访问权限。有权限且使用Git时，先进入准备存放项目的父目录，再运行`git clone '组长提供的真实URL'`（替换整段引号内文本）；不要把占位文本当地址。已有代码不要再次克隆到代码里面。ZIP不能包含可移植环境，`.venv-app`和`node_modules`需在自己机器重建。Git用户运行`git rev-parse HEAD`记录版本；ZIP用户请组长提供对应提交号。

### 检查软件是否可用

```powershell
py -3.12 --version
node --version
npm.cmd --version
```

预期依次为Python 3.12.10、v24.13.0、11.6.2。只做Python分支可跳过后两条。`npm.cmd`用于避免PowerShell脚本策略阻拦`npm.ps1`，无需修改系统执行策略。

若`py`不存在但已知Python安装路径，使用`& '实际安装路径\python.exe' --version`核对；后续创建环境时同样使用完整路径。不要用不明版本的`python`继续。

## 3. 建立项目专用Python环境（全员，只需首次做）

先执行`Test-Path .\.venv-app\Scripts\python.exe`。若已有环境，运行其`--version`核对。若是从其他电脑复制来的环境或版本不对，请组长协助另建环境，不覆盖正在使用的目录。本节默认新电脑尚无环境。

```powershell
py -3.12 -m venv .venv-app
.\.venv-app\Scripts\python.exe --version
.\.venv-app\Scripts\python.exe -m pip install -r requirements-app.lock.txt
.\.venv-app\Scripts\python.exe -m pip check
```

第一条可能没有输出，成功后会出现`.venv-app`文件夹；安装可能下载一段时间，等待结束。`pip check`预期显示`No broken requirements found.`。不需要执行Activate脚本：后文一直写完整Python路径，能避免混淆环境。

```powershell
.\.venv-app\Scripts\python.exe -m pytest tests/smoke/test_startup.py -q -p no:cacheprovider
```

应有passed且无failed；数量按当前代码记录，不用历史数字强行对齐。安装失败不要接着运行：保存错误和失败包名，向组长确认锁文件与下载源，不能删除版本号、批量升级或直接认定代码有错。环境仍有问题时暂停对应分支。

## 4. 公共基线：后端加网页

### 窗口一：后端

在项目根目录运行：

```powershell
$env:AQUAGUARD_DEVICE_ID = 'home01'
$env:AQUAGUARD_HOST = '127.0.0.1'
$env:AQUAGUARD_PORT = '8000'
.\.venv-app\Scripts\python.exe -m edge
```

看到服务启动信息后保持窗口开着。环境变量只对当前窗口有效，新开窗口需重新设置；`.env.example`不会被当前入口自动加载。

打开浏览器，在地址栏输入`http://127.0.0.1:8000/health`。预期是包含`"status":"ok"`和`"device_id":"home01"`的JSON。127.0.0.1表示自己的电脑，不是云服务器。

### 窗口二：前端

重新从项目文件夹打开另一个PowerShell。首次安装时运行npm ci；日后依赖锁文件没变可以跳过安装。

```powershell
Set-Location .\web
npm.cmd ci
npm.cmd run build
$env:AQUAGUARD_PORT = '8000'
npm.cmd run dev
```

打开终端实际显示的Local网址，通常是`http://127.0.0.1:5173/`；端口占用时可能改变，按实际输出。首页应显示“已连接 · 设备 home01”。本节不打开`c.html`。build生成的`web/dist`是构建产物，打开网页仍按dev输出的网址。

完成：保存健康返回和网页截图，解释这里只验证连接。分别在两个运行窗口按Ctrl+C停止；如npm询问是否终止，输入Y后回车。关闭网页不会自动停止后台进程。

## 5. A：完整本机MQTT通信复现

先运行`spikes/SP-02/tests/unit`对应pytest命令，再开始通信；Python命令前缀与第3节一致。

为避免碰到其他服务，本轮统一使用18885端口，三个窗口中的端口必须一致。该配置只监听本机，不能给ESP32连接。

### A1：创建本轮目录及配置（窗口一）

以下路径每次换新后缀，并同步替换后续所有命令。本轮假定名字尚未使用。

```powershell
Test-Path .\spikes\SP-02\data\beginner_20261103_01
```

True就先换名，False才继续：

```powershell
New-Item -ItemType Directory -Path .\spikes\SP-02\data\beginner_20261103_01
Set-Content -LiteralPath .\spikes\SP-02\data\beginner_20261103_01\mosquitto.conf -Encoding ascii -Value @('listener 18885 127.0.0.1','allow_anonymous true','persistence false')
.\.venv-app\Scripts\python.exe spikes/SP-02/src/cli.py generate --directory spikes/SP-02/data/beginner_20261103_01 --count 100
(Get-Content .\spikes\SP-02\data\beginner_20261103_01\manifest.jsonl).Count
```

预期100。这只是生成输入，还没有发送。JSON是一条结构化记录；JSONL是每行一条记录，查看可以用记事本，勿用编辑方式改原始数据。

### A2：启动Broker（仍在窗口一）

```powershell
& 'C:\Program Files\mosquitto\mosquitto.exe' -h
& 'C:\Program Files\mosquitto\mosquitto.exe' -c .\spikes\SP-02\data\beginner_20261103_01\mosquitto.conf -v
```

若安装在其他位置，替换exe路径。第一条用于记录版本，第二条启动并占住窗口；应看到监听18885和运行信息。端口占用时先停在这里，不启动订阅器，也不关闭不认识的进程。

### A3：订阅接收（窗口二，项目根目录）

```powershell
.\.venv-app\Scripts\python.exe spikes/SP-02/src/cli.py subscribe --directory spikes/SP-02/data/beginner_20261103_01 --port 18885 --seconds 120
```

看到READY后，120秒内完成下一步。超过时间自动退出，需要使用新实验目录重新开始完整实验。READY表示订阅建立，不代表已收到100条数据。

### A4：发送（窗口三，项目根目录）

```powershell
.\.venv-app\Scripts\python.exe spikes/SP-02/src/cli.py publish --directory spikes/SP-02/data/beginner_20261103_01 --port 18885
```

该命令结束返回提示符后，等待窗口二自动结束，不提前Ctrl+C截断采集。

### A5：统计和导出（窗口三）

```powershell
.\.venv-app\Scripts\python.exe spikes/SP-02/src/analyzer.py spikes/SP-02/data/beginner_20261103_01
.\.venv-app\Scripts\python.exe spikes/SP-02/src/cli.py export --directory spikes/SP-02/data/beginner_20261103_01
Get-Content .\spikes\SP-02\data\beginner_20261103_01\summary.json
(Get-Content .\spikes\SP-02\data\beginner_20261103_01\accepted.jsonl).Count
```

预期summary的status为PASS、sent_unique与accepted为100、missing/unexpected为空，accepted.jsonl为100行。summary还检查非法、冲突与内容不一致，不只核对数量。

目录中：manifest.jsonl是发送输入；received.jsonl是接收处理日志；journal.sqlite是持久化处理事实；accepted.jsonl是唯一完整DTO；summary.json是集合/内容检查。SQLite不能用记事本编辑。B交接使用accepted，不直接用received替代。

结束后在窗口一Ctrl+C停止自己启动的Broker。本例为突发通信验证，flow区间可能重叠，不能把这100条直接作为特征效果验证。source仍是simulation，不是硬件证据；配置persistence=false不证明Broker崩溃无损。

## 7. C：事务和Mock重试入门

本节无需单独安装数据库软件，Python自带sqlite3。三张表分别记录当前事件、变化历史、待发送消息。

在项目根目录打开PowerShell，每次使用新数据库名：

```powershell
$reproPython = '.\.venv-app\Scripts\python.exe'
$reproRunner = 'spikes/SP-06/tests/manual_runner.py'
$reproDb = 'spikes/SP-06/beginner_20261103_01.sqlite'
Test-Path $reproDb
```

False才继续；True换文件名，init不会清空旧数据。

```powershell
& $reproPython $reproRunner init --db $reproDb
& $reproPython $reproRunner submit --db $reproDb --case open
& $reproPython $reproRunner inspect --db $reproDb
& $reproPython $reproRunner submit --db $reproDb --case replay_open
& $reproPython $reproRunner inspect --db $reproDb
& $reproPython $reproRunner worker --db $reproDb --outcome retry
& $reproPython $reproRunner inspect --db $reproDb
& $reproPython $reproRunner worker --db $reproDb --outcome accepted
& $reproPython $reproRunner inspect --db $reproDb
```

预期：首次创建Event版本1、Transition和PENDING Outbox各一条；重复提交replayed且不增加行；retry后RETRY_WAIT，accepted后ACCEPTED，message_id不变、attempts增长，business_receipt仍为null。这是Mock接受，未发送网络请求。

然后按[SP-06人工指南](../../spikes/docs/C/SP-06/MANUAL_TEST_GUIDE.md)的测试一剩余步骤及测试二至四验证版本冲突、回执、恢复和回滚，各场景按要求换新数据库。故障注入预期ERROR是测试条件，不能与意外错误混淆。

```powershell
.\.venv-app\Scripts\python.exe -m pytest spikes/SP-06/tests -q -p no:cacheprovider
```

完成：保存前后状态、数据库路径、实际命令和测试结果，请另一人复核。该原型不实现完整M6事件状态机，也不验证真实IoTDA。

## 9. 出错时逐条定位

|看到的情况|怎么处理|
|---|---|
|找不到py/python/node|关闭旧终端再开；查安装位置、版本和PATH，先不继续|
|找不到脚本或requirements|Get-Location和Test-Path检查根目录，尤其前端cd web后|
|安装报无匹配版本|记录Python版本、失败包名及安装源；请组长核对锁文件，勿删版本号|
|下载超时或证书错误|记录完整错误，确认网络与系统时间；不关闭证书校验|
|pip check报冲突|检查是否使用.venv-app完整路径，暂停运行，不全局升级|
|服务报缺device_id|在同一终端重新设置环境变量|
|8000或18885被占用|先确认是否自己上次窗口未停止；不结束不认识的进程|
|后端端口需换成8001|后端窗口设AQUAGUARD_PORT=8001；前端窗口同样设8001并重启dev；健康网址也换8001|
|网页未连接但后端可访问|确认dev窗口端口配置、重启dev并刷新；页面只在加载时检查|
|MQTT连接拒绝|确认Broker确已启动、监听18885，publish/subscribe都传相同端口|
|summary缺数据|查READY后是否及时发布、订阅是否先结束；保留旧目录，以新目录重做|
|快照路径失效|先重跑M4再M5，保留原报错，不手改摘要|
|磁盘空间不足|暂停安装和生成，交组长确认清理范围；不要删除项目原始证据|

询问时附：步骤号、所在目录、软件版本、准确命令、完整错误、预期依据和输出路径。命令执行后的`$LASTEXITCODE`可记录上一条外部程序退出码，通常0表示正常；预期冲突用例除外。
