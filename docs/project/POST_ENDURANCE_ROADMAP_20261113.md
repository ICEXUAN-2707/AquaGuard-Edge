# 一小时重跑之后的执行计划

## 当前阶段与本轮运行

工作台功能和人工验收已完成，当前在补持续运行可靠性证据。优化版c253c93的3600秒simulation观测使用新目录audit/optimized-hour-20261113、8048端口、15秒采样及--keep-awake；启动时固定代码，后续文档提交不冒充已测运行版本。最终结果另行归档，本计划不预填PASS。

一小时通过仅代表该版本、该主机和该输入模式在实际观测范围内通过；不等于MQTT持续输入、真实设备、真实云、长期生产或全部Gate通过。原FAIL永久保留。

## 重跑结束如何分流

|结果|下一步|不做的推断|
|---|---|---|
|API、采样覆盖、数据库与退出门槛全部通过|归档去敏元数据和全部采样，整理可靠性PR；接着做MQTT长时专项|不声称根治所有历史503或生产可用|
|再次503，采样覆盖有效|查看同段快照age/TTL、step/tick/CPU、调度空档与睡眠增量；定位后最小修复再定向验证|不提高TTL、重写观测时间或删除失败样本|
|采样空档或显著主机暂停|判本次观测未满足可靠性证据条件，保留主机事件与样本，在受控条件重跑|不以剩余200样本计算连续可用率|
|工具、数据库或进程清理失败|先修观测/完整性/资源归属；业务与工具失败分开记录|不把服务仍活着当作测试通过|

## 实物仍在制作时怎么安排

当前可并行R1/R2、C1离线装配、B1标签及合成评估准备、D1文档/录制脚本；A持续制作并尽早交付一小段真实三源原始样本。没有真实装置和云权限不妨碍这些任务。

## 最近的开发优先级

首选完成R1后立即开展R2，而不是继续增加页面或直接清理磁盘；现有工作台已满足当前人工验收。C1是下一条独立工程主线，先处理run.py仍只装配Mock、delivery.finish使用开始时间及进程隔离装配缺口。B1与H1保持接口交接，避免等实物完成才确定数据语义。

最终作品仍缺三类关键证据：真实感知、真实云/外部应用、稳定可复现的交付材料。当前可靠性工作是在给这三类后续工作提供可信运行基础，不是无限追求无关的生产级重构。
