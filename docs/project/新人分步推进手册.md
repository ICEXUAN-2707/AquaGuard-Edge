# 水知安新人分步推进手册

S1/S2/S3详细执行入口：[逐人操作卡](S1-S3_逐人操作卡.md)。包含A/B/C阅读顺序、可复制的软件命令、共同数据核对及实物实验分工；先执行对应卡片，再用本页定位后续步骤。

更新：2026-11-02。本文是执行导航，不代表新增实测、会签或验收；项目现状以[统一进度表](PROJECT_STATUS.md)为准。

## 每次开工的方法

1. 从下表找到自己最早尚未完成的步骤，记录步骤ID。
2. 只读本步入口，写清预期，再操作；已有成果先复现，不重复开发。
3. 保存准确命令、原始输出与文件位置，按完成判据核对。
4. 失败先定位最早差异，一次只改变一个条件，用文末模板求助。
5. 结束时写下一动作、负责人和依赖。待复核不等于验收通过。

## 先理解链路

|环节|用普通话解释|
|---|---|
|M1采集|读取水流脉冲、干湿、人体雷达|
|M2通信|把观测可靠送到电脑并统一格式|
|M3对齐|组织同一时段的有效观测|
|M4特征|把一段记录概括为统计数字|
|M5情境|依据特征推断情况或拒判|
|M6事件|建立告警，管理人工确认与物理恢复|
|M7保存与云|保存业务变化并可靠同步|
|M8页面|展示状态、事件和操作结果|

目标链路：传感器→ESP32→电脑的通信/对齐/特征/推断→事件→数据库→页面和云。快速水浸信号也进入同一个事件管理环节。

“有水流”是观测，“无人持续用水”是推断，“建立告警”是决策。确认按钮表示人已知悉，不代表探头已干或水已停。

`spikes/`是独立原型，`edge/`是正式服务，`web/`是前端，`reference/`是规格。原型通过不意味着正式服务已接入。

## 分步执行卡

### S0：认路（全员）

前置：无。打开[进度表](PROJECT_STATUS.md)，读统一进度和下一批任务。画一张链路图，标记自己的模块与尚未实现环节；用“湿探头”举例说明数据如何成为事件。

完成：能回答“输入是什么、输出给谁、怎样知道做对了”，能区分模拟、实物和真实云证据。

只学：GPIO是板卡信号引脚；UART是串口通信；MQTT是发布/订阅通信；DTO是统一数据对象；Schema是字段约束；API是程序间接口；Spike是小范围技术实验。

### S1：复现已有软件（全员按模块）

前置：S0。先记当前目录、Python/Node版本、虚拟环境。全员基线看[根README](../../README.md)；A看[SP-02](../../spikes/docs/A/SP-02/README.md)；B依次看[M3](../../spikes/docs/B/SP-03/阅读入口.md)、[M4](../../spikes/docs/B/SP-03-features/阅读入口.md)、[M5](../../spikes/docs/B/SP-04/阅读入口.md)；C看[SP-06人工指南](../../spikes/docs/C/SP-06/MANUAL_TEST_GUIDE.md)。命令目录、启动和停止按各入口执行。

一次只运行一个入口，保存命令、退出结果和输出文件。首次报错先保存全文，不连续换环境或批量升级依赖。

完成：能找到输出并解释其范围。健康检查只证明运行基线，Mock只证明模拟范围。

只学：工作目录、虚拟环境、依赖、端口、进程启停。环境未跑通时暂不学习模型训练。

### S2：共同解释一条数据（A/B/C）

前置：相关原型可复现。A选一条已接受观测，B找对应处理结果，只追踪现有证据支持的链路。

按[线上协议](../../spikes/docs/A/SP-02/WIRE_PROTOCOL.md)解释设备、源、boot、seq、时间、单位、质量与来源；按[时间假设](../../spikes/docs/A/SP-02/TIME_ASSUMPTIONS.md)区分测量与接收时间。B解释纳入窗口、拒绝或未知的原因。

完成：三方理解一致，能解释重传、重启和过期。争议对照[M3决策表](../../spikes/docs/B/SP-03/待确认口径表.md)，记录证据、决定和负责人；不各自改同名字段含义。

只学：JSON、null、唯一身份、去重、单调时钟、窗口。未知不能统一换成0或false。

### S3：一次验证一个传感器（A主做）

前置：按[A零基础采集手册](../../spikes/docs/A/A_零基础实验与数据采集手册.md)补齐P01–P10相关参数并完成E00。缺实物接线、固件或采集工具时，先补齐并短试，不跳到批量实验。本手册不编造未核实的接线与烧录命令。

顺序：板卡E01→单源基线E02→水流E03/E04、水接触E05、雷达E06→失联E07。先确认短采集日志落盘，再重复。

完成：有设备/固件版本、原始值、独立动作标签和指标；水流有标定与独立复测。拔线与静态正常无法区分时记录“不可观测”，不能虚构故障诊断。

只学：供电与逻辑电平、脉冲、串口帧、消抖、标定。学习结果落实到参数表和数据。

### S4：真实数据交接（A/B）

前置：单源通过，S2语义一致。按采集手册E08–E10做三源及交接，覆盖正常、缺失、重启、补发。A核对唯一观测、时间可信度、flow区间和标签；B再进入对齐、特征和后续推断。

完成：双方能解释原始记录、拒绝原因和输出；相同输入、配置、到达顺序与时钟条件可复现。现有按boot划分的有限实验不能证明跨重启连续运行。

只学：采样周期、TTL有效期、乱序、水位线、特征。无输出先查覆盖和拒绝原因，不删除保护或修改时间凑通过。

### S5：本地业务闭环（C统筹，A/B接入）

前置：正式接口按[契约门槛](../contracts/CONTRACT_ACCEPTANCE.md)处理；先接受控fixture再换实物，可与S3并行。

C把工作拆成输入接入、M6状态机、事务保存、查询API、页面五张卡，每卡明确Owner和Reviewer。SP-06事务原型不能替代M6实现。先正常路径，再查水浸快速路径、重复输入、确认、恢复和重启。

完成：页面关联输入与事件；快速路径不等慢窗口；无重复活动事件；确认与物理恢复分开；业务变更与Outbox按约定同事务保存。接口成功和数据库保存成功分别检查。

只学：状态机、幂等、SQLite、事务、Outbox、HTTP。入口为[SP-06](../../spikes/docs/C/SP-06/README.md)与[M6规格](../../reference/reference_02/modules/M6_情境决策与事件状态机.md)。

### S6：算法实验（B主做，A协助）

前置：真实记录、独立标签、trial分组。先按[B地图](../../spikes/docs/B/B部分_项目地图与后续路线.md)核对规则和特征，固定规则及参数，逐个分析错误，再决定是否训练轻量模型。

按trial分组切分训练/验证/测试，同次实验相邻窗口不跨组；测试集不反复用于调参，规则输出不能作真值。

完成：报告逐类混淆、误报、漏报、拒判、延迟及覆盖限制；规则和模型用同一测试数据比较。合成数据不替代实物效果；模型无改善可保留规则。

只学：标签、数据集切分、数据泄漏、混淆矩阵、召回率。数据不足先补实验。

### S7：真实云闭环（C）

前置：账号权限、实例、产品/设备及本地保存/重试能力；账号准备可提前。按[人工指南](../integration/IoTDA_人工对接操作指南.md)与[集成计划](../integration/IOTDA_INTEGRATION_PLAN.md)操作，先一条上报，再断WAN、本地继续记录、恢复补传，用事件标识关联平台记录。

完成：明确回执层级、失败重试和重复处理。MQTT确认不直接等于云业务完成或联系人收到。截图和求助日志隐藏密钥。

只学：鉴权、TLS、产品模型、属性上报、回执、重试。

### S8：联合交付（全员）

另一成员依据记录独立执行启动→正常→异常→确认→恢复→重启→断网补传，逐段注明模拟或实物。保存版本、配置、预期、实际与限制；正式结论按验收矩阵和评审门槛作出，单次演示不替代故障和长期验证。

## 卡住时先查哪一层

|现象|先查|步骤／协助人|
|---|---|---|
|命令或模块找不到|目录、虚拟环境、依赖、完整报错|S1／模块Owner|
|网页打不开|进程、地址端口、健康接口|S1/S5／C|
|串口无日志|按核准步骤查数据线、端口、驱动、板型|S3／A|
|串口有数据而MQTT没有|网络、Broker、Topic、连接日志和授权|S3/S4／A|
|收到但拒绝|原始载荷、Schema、身份、来源、时间|S2/S4／A+B|
|B无输出或UNKNOWN|覆盖、TTL、缺失、时钟和拒绝原因|S4／B，采集问题交A|
|情境与操作不一致|先标签和时间，再原始值、特征、规则|S6／B|
|有判断无事件|M6入口、状态、事务、API|S5／C|
|本地有事件云端没有|Outbox、重试错误、鉴权、映射、回执|S7／C|
