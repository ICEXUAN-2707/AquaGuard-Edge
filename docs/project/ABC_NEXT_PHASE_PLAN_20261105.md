## A：硬件实验推进顺序

1. H0：实物完整型号/模块版本照片、匹配手册、供电与输出电平、引脚和适配记录，Reviewer 核对后上电。以 A_实物实验设计与执行方案.md 为准，不能凭通用模块名字猜接线。
2. H1：ESP32 基础日志、boot_id、sensor/seq、uptime 和重启记录；明确 flow 区间终点及 interval_ms 含义。
3. H2：逐源进行无流/已知体积流量标定、干湿/断开、雷达运动/静止/未检出试验；雷达未检出不作无人真值。
4. H3/H4：三源 LAN MQTT 30分钟基线，再做单源失联、Wi-Fi/Broker/订阅端中断和设备重启；未知不得写成正常，统计损失/重复/恢复。
5. H5：交 B 小批真实 trial，B 核对窗口/特征；交 C 稳定的原始 DTO 样例及故障日志。

每次交付：trial_id、hardware/firmware/calibration/config 版本、操作者与独立记录员、实际操作真值、原始串口/MQTT/标准 DTO、时钟语义、照片/接线与限制。hardware 标记须由可信采集链证明，不能手动把模拟 source 改名。首轮不要求立刻证明整个产品准确率。

## B：先复现，再正确性修订，再性能优化

1. 固定统筹发布的 SHA、Python/依赖；按 B部分_从零复现手册.md，分进程跑 SP-03、SP-03-features、SP-04 及 C 集成测试。C盘紧张时 basetemp 指向项目盘唯一新目录；不删除他人目录。
2. 重生成三源窗口、12 特征和规则结果，记录命令、退出码、样本量、文件哈希、预期/实际差异；不要只读历史 PASS。
3. 优先回归：flow 窗尾端点/调度抖动、TTL 边界、沉默/未知、重复/乱序、boot 更换、拒判、检查点篡改和恢复一致性。
4. 收到 A 数据后先做数据质量审计和特征黄金计算；不适配的时钟/端点通过显式配置或版本决议解决，不改原始标签、不强制把 UNKNOWN 改正常。
5. 测量每窗口计算时间、内存、检查点磁盘增长；小 PR 优化，保留同输入同输出及失败样例。重点研究截断历史对长连续特征和恢复的影响。
6. ML 在首批独立真实 trial 形成后启动：C0–C3，trial 分组划分、真实/合成分开、拒判/误报/漏报/延迟；样本不足就公开限制，仍保留后续可执行受限模型任务。

交付：独立复现报告、最小反例/黄金 fixture、分离的修复 PR 与性能 PR、A 数据问题单、规则/模型/特征版本。不得在优化 PR 中私改冻结 DTO。

## C：IoTDA 按证据分步注册接入

建议架构沿用边缘 Python 作为一个云逻辑设备；ESP32 先留在 LAN MQTT，减少同时改两端的变量。它是待实测的集成选型，不是已证明云链路。

|步骤|任务|退出证据|
|---|---|---|
|C0|确认账户权限、区域、可用实例/资源空间、配额与预算|脱敏资源登记；注册前不假定免费、不擅自购买实例|
|C1|创建独立 MQTT/JSON 产品与版本化物模型|product_id、service_id、字段名/类型/枚举导出；未知状态显式表达|
|C2|注册独立模拟逻辑设备|云 device_id/node_id 与本地 demo01 映射、凭据保存责任人；密钥不进仓库/截图|
|C3|固定设备侧 Python SDK 版本，核实实际接入域名/TLS/CA，最小连接|连接日志、设备在线证据、SDK/映射版本；不能因此认定上报成功|
|C4|先单属性，再单事件消息|云侧实际属性值、关联 message_id/transition_id 的消息记录；属性模型匹配|
|C5|接持久 Outbox 真实适配器|实际回调与传输层确认语义，失败/重试/重复回调隔离；绝不拿 connect/函数返回直接写 ACCEPTED|
|C6|保留 LAN，仅断 WAN，再恢复并重启验证|本地持续事件、积压 Outbox、恢复稳定 ID、真实云接收证据和重复统计|

产品字段先最小化：来源、三源状态/质量/新鲜度、必要流量；事件消息保留 message_id、transition_id、event_id、version。具体云字段与映射另存版本，不能把云模型反向改成本地 DTO。联系人通知、本地 ACK 和传输回执分开。华为云 Web/API 部署与 CodeArts 留证另设任务，不能以 IoTDA 控制台替代赛题应用。

## 跨组节奏与验收

首轮并行：A H0–H2；B 固定 SHA 独立复现及异常黄金用例；C 账户/实例核验→产品→独立模拟设备。三线互不等待硬件全完成或云先上线。

第二轮：A 提交首批真实 trial；B 审计时间/质量并给适配意见；C 最小真实云属性/消息证明，同时补浏览器验收环境。A MQTT→G1 输入接口由 A/C 联合、B 复核，单独 PR，不把硬件、算法、云同时合成一个大改动。

第三轮：硬件→MQTT→B→M6→页面本地联合，再断 WAN/恢复→IoTDA。每个 handoff 记录输入输出、SHA、配置、trial、命令、原始日志及 Reviewer。组会按退出证据推进，不按提交数或测试数推算百分比。

下次组会最低检查：A 至少完成一源真实可追溯日志和 H0/H1；B 给出从统一 SHA 独立复现结果及一份问题/性能清单；C 给出产品/设备脱敏登记及连接/上报阶段的明确状态（不能把注册完成写成云闭环完成）。仍未确定人员、资源或设备条件时显式记录待办，不代填 PASS。
