## 下一阶段按出口推进

### 阶段一：独立评审与集成候选（可立即推进）

1. 评审 PR #14 的只读性、未知值语义及引用边界；评审 PR #15 的进程归属、清理失败、任务默认预览、参数兼容和平台限制。
2. 对固定 PR #13 head 审查数据库拒绝边界、时序证据完整性、阶段断言、预算门槛、停机排空及运行锁；202 项测试作为候选证据，不代填独立评审结论。
3. 意见闭合后，在基于最新 main 的独立集成工作区整合 #14/#15/#13，固定一个集成 SHA，并仅针对新增/交叉接口补回归。合并按评审结果执行，不以 Git mergeable 自动放行。
4. PR #12 不再整批直接合入。去除已被独立工具覆盖的重复范围，重整运行时诊断与优化；涉及 checkpoint 的性能改动单独处理 B 冻结工件版本与复验。不要把过时的调度入口覆盖新版通用监督入口。

出口：审查意见/处置可追溯、集成 SHA 与依赖清晰、没有未解释的 B 冻结源变化、相关回归通过。无需先重做已经确认且未受影响的页面验收。

### 阶段二：实际验证准备（准备可立即做，执行仍暂停）

固定集成 SHA、干净工作区、真实本地 broker 文件及预声明版本、Python 运行锁、全新输出/数据库/端口。检查 C/D 盘空间、运行账号、待机条件和监督方式。按作品目标与短联调基线提出覆盖率/缺口/排除时间/采集耗时/RSS 预算，在正式实验前冻结；不得在失败后移动阶段分母或放宽阈值。

出口：可审查的 plan.json、runtime-lock.json、预算与故障期望，明确采集范围与失败处置。当前不注册任务、不启动 broker、不连接真实云。

### 阶段三：恢复授权后的本地 MQTT 与长期可靠性

先验证真实 broker READY、三源输入、时序文件、业务断言、排空和退出；发现兼容问题先修复短链路。短联调通过后，再执行正常连续期与停报/重复/重启/新 boot 阶段。默认连续期 3600 秒，故障等阶段另加 213 秒，总计划3813秒；不能将不足一小时的正常期当作一小时稳定证据。

出口：固定版本、覆盖达标、正常/故障指标分开、业务断言与退出完整性通过，有实际容量/延迟记录；所有历史失败保留。单纯跑完一小时不是最终作品验收完成。

### 阶段四：真实端边云与最终交付

D1 取得真实三源/标定/独立操作真值和时间映射；B 以真实独立 trial 做按 trial 分区评估，保持 C3 影子边界；D3 验证真实 IoTDA 接收与断 WAN 同 ID 恢复、云上运行的只读 API/Web；最后固定可复现包、合同/Reviewer记录、CodeArts实际使用证据、实验报告、录像/PPT及最新赛规核对。

出口：按冻结 D1–D4 逐项留证，而不是以软件工具 PR 已合并判断作品完成。
