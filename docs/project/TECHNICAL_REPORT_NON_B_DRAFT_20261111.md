# AquaGuard Edge 技术报告草稿：系统与交付

版本：2026-11-11；状态：非B章节草稿，待人工审核。B算法与指标暂缓定稿，真实硬件/云端未验收。

## 1. 目标与范围

使用同一系统展示感知、分析、告警、用户确认与同步状态，并保存可复现证据。当前可复现基线为本地受控仿真，既支持内置输入，也支持仿真观测经本机Mosquitto、SP-02 Journal输入。两种输入共用既有分析、事件、存储、API和前端；不把本地待发队列写成云端已接收。

交付按当前四项管理：D1装置/初版视频、D2三页面工作台、D3云端工程交付、D4技术报告及实验材料。此处不新增范围，也不替代用户最终交付清单。

## 2. 系统组成与边界

- 接入：SP-02对MQTT观测校验并持久化到Journal。edge消费已接受记录；无效、冲突和重复输入不作为新业务观测。
- 分析：沿用M3时间对齐、M4特征、M5情境分析；本报告只描述模块连接，算法正确性与效果待B复验。
- 安全事件：水接触快速路径独立于情境候选，不由影子模型抑制。
- 业务：事件、转换、确认与待发快照存储在SQLite/Outbox；前端通过本地API查询和提交操作。
- 展示：总览、事件确认、实验诊断三页；感知来源、质量、时间、事件状态和同步层级分别展示。
- 云端：已有适配/传输相关实现和本地验证；真实IoTDA接收、补传和业务回执仍需单独证据。进程隔离原型不能替代实际集成验收。

对应代码：edge/app.py、edge/runtime.py、spikes/SP-02/src、spikes/C-business、web/src/c-*.jsx。架构图见NON_B_DELIVERY_NEXT_20261111.md。

## 3. 关键状态语义

确认表示用户已知晓，不等于物理异常已消除；物理恢复证据与事件关闭分开处理。关闭要求已确认、恢复证据仍有效且版本匹配。重复请求通过原幂等键和版本重试；响应不确定时不能换新身份假设前次失败。再次异常产生新的未确认事件，旧记录保留。

输入停报后有效性过期，状态应变为未知，页面不继续显示旧数值为当前正常。新boot重新建立分析历史，退休boot被隔离；恢复本身不伪造用户确认。

同步至少区分本地待发、传输层确认、业务回执及最终送达；当前本地演示不能凭pending下降证明云端收到，更不能凭传输确认声称联系人已收到。

## 4. 运行与配置

完整仓库是交付前提，当前仍依赖spikes。由requirements-app.lock.txt与web/package-lock.json安装依赖，构建web后使用scripts/demo.py检查和启动。运行目录逐次新建，业务DB与MQTT Journal分离，端口冲突不停止他人服务。临时凭据只供本机页面访问，不写入launch.json或录制材料。

默认runtime为baseline，只提供健康入口；连续演示必须显式simulation/mqtt。当前MQTT基线仅支持demo01与simulation来源，真实硬件需明确适配与验收。端口探测是启动前检查，存在探测后被占用的竞态，最终以服务启动结果为准。

本地证据ZIP不提交远端；归档去敏的结果与摘要。数据库为逐库备份，不是跨库原子快照；检查点保留原路径，换机重放需要路径映射。哈希证明包内文件一致，不证明真实环境效果。

## 6. 当前限制与待验收

本系统是本地演示交付候选，不发布为长期无人值守生产服务。历史日志、检查点和Journal保留增长；长时墙钟运行、容量预算与保留策略仍待专项验证。不能把几分钟仿真时间推断为数小时墙钟稳定性。

尚缺真实装置采集、真实IoTDA关联接收/断网补传、相应工程流水线证据及人工验收。视频、PPT未录制/完成即保持待交付。B章节等复验提供明确工件与结论后再接回，不用旧100%数值填充。
