## 4. 第一轮集成验收：最小场景

1. 持续模拟输入：30 秒窗口/5 秒步长（暂定）多次发布，不需要手动导入旧工件。
2. 模拟人员在场用水，实时页显示 `ATTENDED_FLOW`，不产生无依据的疑似无人事件。
3. 模拟人员未检出且持续流水，在证据足够且规则阈值达到后出现 `POSSIBLE_UNATTENDED_FLOW`，并展示规则原因与源质量。
4. 同时水接触：在等待下一慢窗口期间触发一次快速 `WATER_CONTACT` 事件；ACK 后仍湿，事件仍有效。
5. 模拟 WAN 中断：SQLite Outbox 继续待发；真实云端测试后再验上传/回执。
6. 页面连续更新、错误/过期/缺失显示 UNKNOWN；记录用户实际浏览器操作和网络日志。

## 5. 推进纪律

- 各线用 PR 合并，统一 Owner 和独立 Reviewer，契约修改先申报差异，禁止跨模块无审查修改。
- 使用真实 `source=hardware` 需要可信输入与时间映射证据；模拟 `source=simulation` 不得发送真实联系人通知。
- 先在 `spikes/` 复现及回归，再迁移为 `edge/` 正式服务；不能直接复制/改名后宣布工程化完成。
- 每项验收记录：输入、期望、命令、输出日志、设备/云证据、版本/commit SHA、Reviewer、限制。
- 如果官方赛题说明与这里的部署/材料范围冲突，以官方原文修订**赛题合规计划**；不自动更改既有安全/事件架构。
