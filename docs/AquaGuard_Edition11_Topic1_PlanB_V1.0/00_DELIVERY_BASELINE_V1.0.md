## 1. 作品一句话与业务边界

**定位**：一个面向独立居住/居家关怀应用需求、监测**单个受控用水支路**的端边云协同异常监测系统，支持多源异构感知、可信时序融合、可解释情境分析、事件留痕和离线自治。

**严守边界**：目前不是全屋漏水检测、无人真实身份确认、医疗诊断或认证安全产品；不做自动关阀/市电电器操作/真实联系人通知。人体雷达“未检出”≠已证明无人；设备停报≠水流为零。校园公共设施仅可在主场景稳定后进行配置迁移演示。

**三大技术创新证据链**：①异构时序及缺失数据质量处理；②分情境规则与可评估轻量 ML 对照，拒判优先于伪造确定性；③快速安全路径 + 周期情境路径统一事件机制，断云本地处理、Outbox 恢复。

## 2. 四类固定最终交付物

### D1｜桌面实体感知台架
- **组成**：低压受控循环/接水水路、YF-S201、FC-37、LD2410C、ESP32、必要电平适配及安全固定结构；边缘电脑承担 Python 推断。
- **演示能力**：开/关流量、人在/离开传感器区域、水接触干/湿、传感失联或重启；实时记录来源、设备时间/接收时间和传感质量。
- **验收**：三源真实观测→LAN MQTT→边缘服务；已知体积流量标定、湿/干及雷达静止场景有独立操作真值、原始日志、版本/接线记录；台架低压隔离、漏水托盘，ESP32 不直接接未经核实的 5V 高电平输出。
- **降级**：硬件没有完成时，可保留显式标注的模拟演示，但不能把 D1 标记为真实验收 PASS。

### D2｜三页面 Web 工作台
- **实时总览**：三源状态与时间新鲜度、UNKNOWN、质量/来源、情境、风险级、独立安全信号、云同步状态；受控模拟与真实硬件明显区分。
- **事件确认**：一事件唯一 OPEN、事件时间轴、OPEN/RESOLVED/CLOSED、确认与物理状态独立；ACK 不等于水已消失，失败/冲突有用户反馈。
- **实验诊断**：可加载 trial 和预记录回放，展示 C0/C1/C2/C3 对照、误报/漏报、召回、拒判、延迟与故障证据；原始数据保留可追溯引用。
- **验收**：三页面实际浏览器点击、窄屏、错误/过期场景验证；持续输入引发页面真实更新（不是仅构建成功/静态 seed）；模拟演示有身份标识。

### D3｜华为云协同与云上应用
- **本地边缘为事实权威**：M6+SQLite 负责告警、确认与 Outbox，IoTDA 不能代替事件库。
- **IoTDA**：真实设备注册、属性上报与事件消息上报；传输确认与业务回执/联系人送达区分；外网中断时本地仍处理并保留待同步消息，恢复后有稳定 ID 与重试证据。
- **云上应用部署（赛题一专门增加）**：在华为云部署可访问的演示应用入口，至少可运行 Web UI 与**真实云端运行**的演示/只读 API，能展示明确标注的模拟 trial；在消息转发/接收链路经验证后可加入真实 IoTDA 业务事件查询。**静态介绍页或单纯 IoTDA 控制台截图不得冒充已部署的应用。**
- **部署选型待技术 Spike**：可评估华为云 Flexus/ECS 等低成本运行方案；不预设具体实例、RDS、Redis，避免新开资源前无法控制费用。云端只读演示不是远程 ACK/家属通知系统；前端不得持有设备密钥。
- **赛题一开发工具**：必须真实使用华为云码道 CodeArts 代码智能体参与一个或多个可追踪开发/测试/部署任务，保留提交记录、提示词摘要、构建/部署证据；Codex 可以继续使用，但不能代替 CodeArts 的真实使用要求。

### D4｜AI 技术实验与比赛交付
- **AI 的实际运行要求**：训练/引入一个适配三源融合特征的可执行轻量 ML 情境模型（如决策树/随机森林，具体由真实数据决定），可在实验/影子推断链路运行并产生可追溯结果；低数据量时不宣称优于规则，不允许 ML 覆盖快速水接触信号。若样本不足，应公开“不足以证明提升”并保留可运行的受限 AI 实验，而非虚构指标。
- **实验四组**：C0 水流阈值；C1 即时多源规则；C2 时序/上下文规则；C3 融合特征轻量 ML。独立 `trial_id` 分组划分，合成/真实分离；保留负例与不可区分情景、拒判率。
- **量化指标**：误报率/每小时误报或每 trial 误报、异常召回、Macro-F1（如样本充足）、拒判率、分层响应延迟、断网恢复时间与事件重复率；指标与样本量、置信区间或限制一起展示；不预写“97% 准确率”等未经验证数据。
- **比赛材料**：代码及运行说明、产品设计说明、系统架构图、技术实验报告、原始匿名 trial/标注规范、3–5 分钟完整演示录像（按最终官方时长要求调整）、答辩 PPT、赛题合规清单。

## 3. 最终现场演示剧本（3–5 分钟；录屏可复现）

| 序号 | 现场操作 | 必须出现的产品反应 | 要保存的证据 |
|---|---|---|---|
| 1 | 正常在场用水 | 三源有效观测、情境为有人用水、无误报 | MQTT+UI 时间一致日志 |
| 2 | 离开后持续流水 | 出现 POSSIBLE_UNATTENDED_FLOW（证据足够时）及风险事件/提示 | window、FeatureWindow、M5 决策、M6 事件 |
| 3 | 探头接水 | 快速安全提醒，不等待 30 秒分析窗；可以与有人用水并存 | SafetySignal 到事件的延迟 |
| 4 | 点击人工确认 | ACKNOWLEDGED，但物理 ACTIVE 可保持 | EventTransition 与 UI |
| 5 | 断 WAN 后恢复 | 局域网仍运行，Outbox 保留，恢复后可追踪云端接收 | 出站重试及真实 IoTDA 证据 |
| 6 | 进入实验页 | 规则 vs ML 指标、源数据和失败反例 | trial 和评估报告 |

若正常阈值较长可采用清晰标识的 `demo_profile` 或录像回放；不得偷偷压缩阈值并据此声称正常模式的时延。

## 4. 不可变设计约束与版本关系

**不推翻** ADR-001～005：情境/安全/质量分离；真实试验标签独立于规则；快慢双路径汇入同一事件 FSM；本地/IoTDA/联系人三级分开验收；事件生命周期、ACK、升级与每条消息云同步状态独立且事务性 Outbox。

**冻结范围**：赛题、作品形态、四类交付物、单支路主场景、三页面、必须可展示的完整闭环、安全和来源边界。

**仍待冻结**：Contracts V1.2 C0 会签、真实硬件时钟映射/采样率、实测阈值、云实例与数据流转方案、CodeArts 实际研发流程、云端部署方案、AI 模型/样本量及性能门槛、最终赛区材料细则。上述问题不可由 Codex 单方面修改公共契约。
