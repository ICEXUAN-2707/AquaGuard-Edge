## 1. 可执行命令和当前基线

从仓库根目录执行。两个虚拟环境职责不同：`.venv` 执行 `jsonschema` 测试；`.venv-app` 执行 Pydantic DTO 和服务测试。测试命令退出码必须为 0，且报告非零收集量；不能用 skip、xfail、仅 mock 或未创建的路径充数。

```powershell
.\.venv\Scripts\python.exe -m pytest reference/reference_02/tests -q -p no:cacheprovider
.\.venv-app\Scripts\python.exe -m pytest tests/contracts tests/smoke -q -p no:cacheprovider
```

2026-10-27 最终重跑结果：结构测试 **45 passed**；DTO/API 模型与服务启动合并测试 **32 passed**，两个命令退出码均为 0。机器时间格式由 JSON Schema 的 offset 模式和 Pydantic 时间解析共同把关；Schema 单独通过不等于语义验证通过。

## 4. CT01–CT16 最低行为断言

正式验收以 `reference/reference_02/tests/BEHAVIOR_TEST_MATRIX.md` 为索引，每条至少保留输入、期望 DTO/数据库状态、运行命令、测试输出和负责人。以下四组不能只靠单对象模型测试：

1. **采集与时序 CT01–04/13/16**：缺失不变 false；重放去重按 `(device,boot,sensor,seq)`；乱序和水位线按事件时间；永久沉默仍发布；未知时钟降级；相同输入时在线/离线特征一致。
2. **安全与事件 CT05–09/14**：有人流水和水浸并存时仍告警；快慢路径只建同一事件；ACK 不清除物理湿态；同键同载荷返回原结果、同键不同载荷或旧版本 409；事务任一写点失败全部回滚。
3. **断网与来源 CT10–11/15**：WAN 断开仍有 C1 本地结果及待发 Outbox；重启后 message_id 稳定且 transport/business 回执分层；simulation/mixed/unknown 均不能调用真实联系人发送器。
4. **实验 CT12**：同一 trial 的相邻窗口不可跨训练与测试分组；固定 split、模型/特征版本和真值来源。

## 5. PR 验收记录模板

每个合同或消费端 PR 必须填：修改的 CC/CT 编号；输入合同版本；字段/单位/枚举/缺失语义差异；受影响生产者和消费者；正反 fixture；实跑命令、收集数、通过数及退出码；迁移与回滚；未验证 Gate；A/B/C 对应评审意见。若改动公共字段或业务语义，先更新候选规范、Schema、样例和两层测试，再合入实现。仅靠截图、手动演示或“预期通过”不能满足门槛。
