# M4-R07｜检查点与模拟技术验证收尾

日期：2026-10-29。结论：M4 限定范围的离线模拟原型已完成本轮收尾；正式模块验收仍 PARTIAL，待独立Reviewer、契约会签和硬件语义验证。

## 本轮开发
新增 checkpoint.py：保存完整回放快照（格式版本、特征版本、窗口身份和时间边界、历史输入、配置、计算结果），以规范JSON的SHA256命名，先校验候选 FeatureWindow 的跨字段约束，再写临时文件、flush/fsync、os.replace发布。恢复时检查摘要、版本、可选预期配置，并重新计算核对结果。生成的 state_checkpoint_ref 指向实际存在的快照，不使用占位符。
这里是“保存历史、恢复后重算”的实验方案，未实现压缩状态的有界流式检查点。输入历史可以包含完整离线实验文件，计算仍按每个窗口截止过滤；不宣称在线时已经拥有未来输入。

## 多次交叉验证

6. 演示生成两份三源候选 FeatureWindow，保存后恢复一致；实际输出 evidence/r07_feature_windows.json，快照 evidence/checkpoints/。

## 阶段Review与边界
- 本轮由同一代理代码自检和独立算法对照，非独立Reviewer验收。
- 内容摘要用于完整性与身份核验，不是数字签名或来源真实性证明。
- 快照引用为本机绝对路径；跨机器交付需要重映射工件路径。
- 完整历史保存/重算非有界内存方案，尚无压力或性能承诺，也无并发writer正式验证。
- 恢复返回历史和最后窗口，调用方组合新增输入；不是完整实时调度器，未保证任意重复/迟到新输入自动合并。
- 跨boot、真实时钟和flow区间端点仍按M3限制；候选Contract未会签，不可宣称生产就绪。

## 收尾判定
原定M4实验链路已覆盖：字典→基础流量→状态/计数→历史连续时长→统一十二特征→真实快照与恢复→候选DTO输出和演示。
可以进入后续独立规则验证准备；正式集成前仍需Reviewer检查本报告、M3口径决策表及硬件时间证据。后续M5不得把这些模拟结果当真实家庭准确率。
