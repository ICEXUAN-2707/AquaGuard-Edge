# A 技术验证软件开发实施计划

日期：2026-10-29。状态：待开发。范围：SP-02软件验证及SP-01固件准备/实物联调；prototype_only。

## 1. 目标和依据

交付一套能够重复运行的“模拟器/ESP32 → Mosquitto → 标准化 → 身份判定 → 日志与统计 → B回放文件”实验工具。复用现有候选DTO，保留原始证据。硬件未到位也能完成SP-02；SP-01实物验收单独进行。

依据：A_任务单.md、A_双线开发计划.md、候选合同D1、edge/contracts/models.py、M1/M2模块规格。历史M2的“双格式/合包拆分”仅在获得实际旧协议及fixture后实现，首轮不猜测兼容格式。

## 2. 硬件手册是实现门槛

当前reference目录未发现匹配实物的板卡原理图、YF-S201/FC-37手册及LD2410C完整协议。已有采购建议不能作为接线依据。硬件相关数值、引脚和协议常量均保持待确认，缺资料不填默认猜测值。

每种设备建立manual_manifest记录：实物型号/硬件版本/照片、厂家、文档名称/修订版、原始URL、获取日期、本地路径、SHA256、适用固件、页码/章节、复核人。来自卖家的资料须确认与实物匹配；博客和其他型号示例仅作线索。

建立参数追踪表，每项为“参数 → 手册页码/章节 → 软件配置/代码位置 → 验证用例”。手册修订或设备换型时重新检查受影响项。

|设备|编码或上电前必须确认|未确认时允许工作|
|---|---|---|
|ESP32开发板|准确芯片/模组、原理图、供电入口、GPIO限制、启动/Flash占用、UART映射|主机软件、抽象驱动接口；不生成可上电的默认引脚配置|
|YF-S201|供电、输出电路及逻辑电平、脉冲含义、工作流量、安装要求|标定计算器及合成脉冲测试；不写死通用系数|
|FC-37套装|探头及比较器板版本、AO/DO、电平、输出极性、阈值设置|消抖算法纯逻辑测试；不假定高/低就是湿|
|LD2410C|准确型号及固件、供电/逻辑电平、UART参数、帧头尾/长度/字节序、目标状态语义|解析器接口；取得协议后才能制作协议黄金字节流|

硬件配置增加状态UNVERIFIED/VERIFIED。硬件模式启动前检查资料、引脚表及复核记录齐全；缺失则拒绝启动。运行前仍需人工复核供电/电平和接线，软件配置不能证明电气安全。具体电压、波特率、GPIO编号均不得从购物标题推导。

官方资料起点见双线计划；最终固件路线在实际板卡和手册核对后固定。原计划的Arduino-ESP32仅为候选，不构成已选定框架版本或驱动实现。

## 4. 数据和时间决策

- 线上协议单独版本化，不能将“缺received_at的设备载荷”冒充完整DTO。订阅端提供权威received_at，保留设备原始内容于审计日志。
- 第一轮只支持无可信设备时钟模式：event_time=null、time_basis=RECEIVED_FALLBACK。设备上传同步时间时，在同步验证功能完成前明确拒绝/隔离该模式，不悄悄相信时间。
- device_id固定；boot_id每次启动生成；seq按传感器递增、在同一boot内不回绕复用；重发同一测量保留身份与内容。uptime采用单调计时，需验证框架计时范围和回绕扩展。
- observation_id由规范编码的(device_id,sensor_type,boot_id,seq)确定性生成，模拟器与固件共用黄金fixture验证编码一致。
- 去重摘要排除边缘received_at及传输元信息；同一重发的接收时间变化不能造成内容冲突。相同组合键但测量内容不同是conflict；同observation_id对应不同组合键也拒绝。
- 乱序以各(device,sensor,boot)已接受seq最大值判定，先判重复/冲突。旧boot消息迟到不能触发切回旧启动状态；boot变化保留多轮记录，不按到达顺序推断新旧启动的真实先后。
- 原始接入quality仍为valid/invalid/unknown，duplicate等分类放sidecar，不能绕过DTO入口约束。
- source由受控模拟/硬件连接配置与白名单核对，载荷自称hardware不作为可信授权。实验不接真实通知。
- flow无合法标定或无法形成数值时走status；water/presence未知使用null及合适quality。不可观测的拔线不能凭空诊断。

## 5. 持久化、重连与故障策略

首轮MQTT 3.1.1、QoS1、观测retain=false。固定client_id和明确clean_session配置；Broker持久化开/关分别测试。status可验证LWT，但LWT仅说明连接异常，不能证明具体传感器故障。

纯内存客户端会话不能承诺进程重启后恢复发送。模拟发布器使用实验发送manifest/待发记录重放，保持业务身份；ESP32首轮离线队列有界、明确容量与溢出计数，若不持久化则报告断电丢失范围。设备持久化补发作为后续可选任务，不预先承诺。

订阅端采用独立实验SQLite持久化身份及处理结果，重启后重复可继续识别。实施时核对所选Paho版本的手动确认能力及回调语义：在处理事务持久化后再确认；崩溃前后注入验证，不能只靠接口名称认定可靠。原始日志与事务库不具备跨文件原子性，导出以事务记录为准，日志缺口要显式报告。

磁盘写失败、队列满、无效UTF-8/JSON、超大报文均记录明确错误；队列满不能悄悄丢弃后仍给PASS。有界超时退出并产生未完成清单。网络重连退避不阻塞传感采集。

|F5 三源调度与网络|非阻塞采样、有界队列、Wi-Fi/MQTT恢复、可观测溢出|断网时仍采集；逐项报告缓存容量、丢失和恢复；硬件来源单独输出|

采样周期、消抖时长、串口超时、滤波和低流量阈值先列待验证参数；从手册约束与实际实验得到，不直接复制B的TTL或窗口参数。串口无新有效帧超过已评审超时后为未知，不以最后一次无人状态持续输出。

## 8. 开发批次和交付

1. **S1 环境与协议**：探测环境；WIRE_PROTOCOL、错误码、身份/统计口径、模拟fixture和目录骨架。退出：字段映射明确、待确认项可追踪。
2. **S2 纯逻辑**：normalizer、identity、journal、analyzer和单元测试。退出：异常分类和重启去重有可重复证据。
3. **S3 本机通信**：publisher/subscriber、回环Broker配置、100条自动编排。退出：真实Broker唯一集合核对通过。
4. **S4 故障与交接**：受控故障、会话/retain对照、TIME_ASSUMPTIONS、B导出、REPORT。退出：SP-02逐场景评级及Reviewer复核。
5. **S5 手册与驱动**：手册归档和参数追踪，F0–F4。退出：匹配实物资料复核及单源实测。
6. **S6 实物通信**：F5、受控LAN配置、三源联调与SP-01报告。退出：硬件与通信证据分别齐全。

S1–S4可立即开发，S5/S6依赖准确设备及手册。每批完成后提交可检查代码、命令和证据，再进入下一批。当前只完成计划，不修改实验状态为PASS。
