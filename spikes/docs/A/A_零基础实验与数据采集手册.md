# A 零基础实验与数据采集手册

版本0.1，2026-11-02；规划稿，prototype_only。用途：让首次参加实验的成员知道做什么、怎样操作、记录什么和怎样检查数据。设备参数和硬件工具尚未确定，本版不是可直接照接的接线/烧录说明。

## 1. 使用方式和执行门槛

先读第2–5节，建立记录目录；完成E00后才进入E01；单源实验完成再做三源。每个实验先完整读完步骤再操作。操作员负责动作，记录员负责按键和标签，复核员检查结果；人员不足可以一人兼任操作和记录，但最终需另一人复核。

全文“待填”不是可忽略项。供电、电平、接线、串口、固件构建/烧录、硬件采集命令及停止方法未确认时，涉及实物的实验标记BLOCKED，不先上电尝试。可以先做目录、表格、标签练习和既有SP-02模拟实验。

## 3. 先学会记录：run、trial和真值

- run：一次采集程序从开始到停止的运行。
- trial：一次预先定义的实验条件，例如“中档流量标定第2次”。一个run可以含多个trial，但标签要能分开。
- 真值：独立记录的实际操作/测量，如量杯体积、人工进入房间；不能用传感器自己的输出作为真值。
- 原始数据：设备实际输出及接收日志，不覆盖、不手工修正；处理结果另存。

推荐编号：`20261102_E03_mid_cal_r02`，分别表示日期、实验、档位、标定/复测和重复号。设备重启或参数改变必须记录；模型拟合/复测数据分开。

目录模板（待建立为实际采集工具的输出约定）：

```text
experiments/hardware/<run_id>/
  trial.json                 # 方案、人员、设备/固件/参数版本
  raw/serial.jsonl           # 串口字节及解析值，保留原始时间
  raw/mqtt.jsonl             # 原始载荷与接收时间/传输元信息
  labels/actions.csv         # 独立动作和真值
  measurements/volume.csv    # 水流体积、脉冲、时长
  photos/                    # 装置与条件，隐去隐私/凭据
  derived/                   # 计算、校验、图表，不能覆盖raw
  report.md                  # 结果、偏差、失败、限制
```

所有时间附时区；设备uptime单独保存，不把它伪装为日历时间。若人工标签和设备不共钟，记录同步方法与误差，不直接计算精确时延。

## 4. 每次实验通用操作卡

### 开始前

1. 查E00和P01–P10相关项目是否齐全，有未确认项则停止对应实物步骤。
2. 检查托盘、水路固定、电子部分远离水；确认安全停止方法和负责人。不得接家用真实管网或改市电。
3. 选择尚不存在的run目录，填写trial.json及预定阈值，照片拍清设备和安装位置。
4. 固定本轮固件、校准和配置版本，记录所有参数；过程中不随意旋钮调参。
5. 按P10启动采集；做30秒短试，检查日志有增长、字段可读、设备身份正确、磁盘空间足够。
6. 确认操作标签能记录；口述“开始”后由记录员写start事件，再开始动作。

### 过程中

一次只改变一个条件。记录员逐次填写动作，失败也记，不因结果不好删除某次。设备重启、溅水、气泡、人员闯入、调参、日志中断立即加备注；可能影响安全则先停止并断开安全供电，再处理。

### 结束后

1. 写end事件；停止动作；按核准顺序停采集和设备，先确保水路不继续流出。
2. 打开日志检查首/末时间、行数、设备、boot、序号和错误，不只看终端滚动。
3. 只复制原始文件作处理；记录缺失、截断、程序退出码，不手补成正常数据。
4. 统计输入与输出；复核员确认条件和文件对应后签名，备份到项目规定位置。
5. 给出PASS/PARTIAL/FAIL/BLOCKED。尚无判定阈值只能写“已采集/待判定”，不能写精度PASS。

## 5. 逐项操作步骤

### E00：到货与准入

逐个摆放设备，拍正反面、标签及接口；按参数页登记型号。取得手册后逐项标出供电、信号电平和引脚出处，让复核员检查适配电路。水路在电子设备未接入的情况下先做低压台架密封检查；漏水先修复。只在复核后的供电/引脚方案下测量，不指示新手带电挪动表笔到未知针脚。

输出：设备清单、参数页、接线表、复核签名、装置照片。缺任何关键电气资料则本实验BLOCKED，后续硬件步骤不执行。

### E01：板卡与记录链路

先按P05部署不启用传感器的基础固件。开始串口采集，记录板卡身份、boot和启动日志；观察60秒，确认uptime增加。按已确认的复位方式重启，记录动作和新boot；重复5次。新boot应变化，同一boot各源seq遵守已定义作用域；重发同一测量身份不变。

检查：日志重启点明确、无同身份异内容、计时未异常倒退；只有uptime而无同步证据时event_time仍为null。仅串口成功不代表网络成功。

### E02：单源原始基线

每次仅启用一个已核验驱动。水流保持无流，水接触保持干态，人体保持视场无人；每源连续5分钟，开头和结尾拍照记录条件。有人进入、触碰线材等干扰写标签，不擅自删除。

输出：原始值随时间图、有效样本/帧数、无效/未知数及误触发事件。无脉冲不可用于证明水流传感器在线；无人状态只对记录视场和条件有效。

### E03：水流标定与复测

准备量具和接水容器，记录刻度分辨率。选择手册范围内低/中/高档，先短试确认管路稳定、无明显气泡。采用同一种收集起止方法：收集时间范围与脉冲计数范围必须一致；人工移杯导致的边界误差需记录，不能用不同时段数据相除。

每次操作：记录trial_id→固定档位→记录脉冲累计初值和起始时刻→收集水→记录终值及结束时刻→等液面稳定后读体积→记录溢出/洒水/气泡→复核后倒水准备下一次。每档5次标定。标定结束固定calibration_id和系数，另每档3次复测；复测期间不重新拟合。

处理：N=终值−初值，Δt=结束−开始（秒），K=N/V（pulse/L），参考Q=60V/Δt，估计Q=60N/(K×Δt)。全局常数模型可用K=sum(N)/sum(V)，其适用性仍要看分档误差；不适用时保留结果再讨论模型。

误差=估计−参考；V>0时相对误差=100×误差/参考。报告各档每次值、平均偏差、平均绝对误差、最大绝对误差和量具限制。V=0不用相对误差；计数溢出/重启跨界的记录不能直接相减，要标无效或按已验证规则重建。

### E04：开停与低流

开始无流基线，记录员标记每次开始开流和确认停止动作，按已定观察时间等待设备响应，再重复，共10次。低流探索与量程内记录分开，档位改变必须标记。

处理：动作到首次有效检出及稳定输出的延时分别统计；动作时刻不精确则只报区间或近似值。停流后区间内仍存在脉冲可能是统计窗口效应，先核对区间端点，不直接叫误报。

### E05：干湿与消抖

固定探头位置、浸湿方法和模块阈值，记清怎样判定“已湿/已干”。开始时拍干态，记录wet_start并施加相同接触条件，等待预定观察时间；记录water_removed并移除水，再按统一干燥方法等待dry_confirmed。移除水不等于探头立刻干燥，这两个时刻不能混用。

先做10轮原始表征，统计抖动，再确定消抖参数并记录版本；用新10轮验证，不用调参轮次当独立精度结果。保存原始电平/模拟值、稳定状态和独立标签。每轮记录漏检、额外触发、未恢复及响应时间；环境温度/表面残留等影响写备注。

### E06：人体存在

在地面标出两个允许位置，量距离并记录角度/高度，固定雷达配置。先无人60秒；人员按标签进入指定位置，分别移动或坐立保持自然静止，每段60秒，状态/位置各5段。完成进入/离开各10次。用计时提示动作但不根据传感器结果决定何时结束；无人段确保其他人不在声明视场内。

处理：按时间对齐独立标签和设备状态；统计present/absent/unknown时长及状态转换。帧率不均时不能用样本个数比例代替时间占比。分别报告检出、错误在场、未知占比；unknown单列，不并入正确无人。人体状态转换附近可设置预先声明的过渡区，原始数据仍保留，报告被排除时长。

### E07：传感器失联

先正常运行并标记有效状态。按E00批准的可断开方式操作，不带电拔未知引脚；记录disconnect，再等待P06超时及观察区间，记录unknown出现时刻。按批准方式恢复，记录reconnect与首次有效恢复。每源3轮。

若水流/接触静态接口没有自检能力，拔线可能与正常状态不可区分，结果写“不可观测”，不能为了PASS造出故障标志。雷达失联以有效帧超时为依据，不以没有目标作为失联。unknown期间不得自动清除业务事件。

### E08：三源场景

单源通过后接三源，运行30分钟。在时间线中依次安排：干+无人+无流、干+有人+有流、干+无人+有流、湿态，安全可行时每场景3轮。不要把四种场景全部叫“漏水真值”：物理水接触、人员、流动是独立真值，漏水原因判断不在采集验收范围。

处理：校验三源身份/周期/来源与日志缺口。生成同一时间轴的flow、wet、presence及动作图；检查并发后串口解析、脉冲计数或上报是否受阻。时间不可信时不强行插值对齐为准确同时发生。

### E09：网络与进程恢复

每轮正常观察60秒，记录failure_start，只中断一个对象：Wi-Fi（10秒或60秒）、本轮Broker、订阅器或ESP32；到时恢复并写failure_end，再观察60秒。不要停止别人共享服务。设备重启属于新boot，网络恢复不应凭空变成设备重启。

处理：用设备产生清单作为分母，分别比较产生、入队、丢弃、发送尝试、Broker确认、唯一接受及重投。记录缓存容量、溢出、是否跨断电保留。恢复耗时从明确的恢复动作/连接建立算起，区分首次连接、重新订阅、首次有效观测。只有接收日志而无产生清单时，缺失率写不可计算。

### E10：交给B

先核对完整DTO及唯一身份，只导出已接受观测；保留异常日志另交。标明flow区间对应真实测量起止，核对是否重叠；无可信测量时间的补发单独隔离。按正常、单源未知、重启、补发四组执行回放并保留窗口与错误结果。

现有handoff_b.py仅将device/boot划分为独立有限实验，不证明跨启动连续流；引用用(experiment_id,window_id)。M4原型不是正式FeatureWindow检查点，M5端到端需另验。B拒绝数据时先核对时间和原始区间，不删除拒绝保护或修改历史时间凑通过。

## 6. 数据处理标准流程

1. **归档**：冻结raw副本，计算hash；把实验方案、手册/固件/参数版本一起保存。
2. **检查**：文件是否完整；UTF-8/JSON/CSV能否读取；单位、时区、设备/boot/seq、必填值和日志间断。写check_report，错误不静默跳过。
3. **分段**：按trial、device、boot和配置变化分组；断网/无效段作标记。标定与复测严格分开。
4. **去重**：按已定义组合身份，重传只计一次；同身份异内容单列冲突，不能选一个覆盖。原始发送尝试仍保留。
5. **时间校核**：仅在共钟/映射有证据时计算跨设备时延；使用同设备单调时钟计算自身区间。补发接收时间不改写成测量时间。
6. **清洗派生**：新增validity、exclusion_reason及规则版本；不修改原始null为0/false。排除项计数和原因随报告提供。
7. **计算**：按E03–E09口径算指标，所有比例写清分母和单位；N/A不用0代替。
8. **画图**：流量参考与估计散点/分档误差；干湿/人体原始与稳定状态时间轴；故障及连接时间线。显示缺失与未知，不将断点用连续线隐藏。
9. **复核**：随机选每类至少一轮，从原始数据手算/对照到指标；检查程序输出是否可重现。
10. **结论**：分场景评级，列已知限制、失败、重做原因与下一步。小样本报告观察结果，不包装为普适准确率。

### 表格字段约定

|文件|最低字段|
|---|---|
|trial.json|run_id、trial_id、experiment_id、phase(calibration/validation)、设备/固件/配置版本、人员、参数、阈值、环境、开始/结束|
|actions.csv|trial_id、action_id、label_time、clock_basis、动作、位置/条件、观察真值、时间不确定度、备注|
|volume.csv|trial_id、档位、phase、初末计数、初末uptime、体积L、量具分辨率、异常、calibration_id|
|原始串口|run_id、接收UTC/单调时钟、device/boot、原始字节、设备uptime、解析结果/错误|
|MQTT记录|topic、接收时间、qos/retain、原始载荷、校验/身份分类；正式DTO不塞实验字段|
|metrics.csv|trial_id、metric、value、unit、分子/分母或样本数、规则版本、排除数量、限制|

这些是待实现的记录规范，不是当前工具已经支持的字段。原始日志不得为了套表丢弃额外诊断信息。

## 7. 常见错误和停止条件

- 终端有字不等于日志已落盘：先看文件增长，再开始正式动作。
- 参数改变没有标签：停止当前trial，保留数据，创建新版本/新trial。
- 看结果不好就重来但不记录：错误。原轮次保存，重做说明原因。
- 日志缺失、动作忘标：标PARTIAL或重做，不凭记忆补精确时刻。
- 探头仍湿却写dry：以独立观察记录实际状态，移水和干燥分别标记。
- 仅有MQTT确认就说设备数据没丢：错误，必须核对产生清单和唯一接受集合。
- 异味、异常发热、漏水接近电路、供电不明、线松动：先停止并按核准方法断电，由有经验成员处理；不让新手边试边猜。
