# M3 技术总结与 M4 敏捷开发计划

日期：2026-10-29。阶段：独立技术验证。M3 / SP-03 为 PARTIAL；M4 当前只完成规划，未实现。候选 Contract 未代替正式会签。

## M3 完整思路
观测先通过 raw DTO 校验，按接收时间回放；测量时间负责对齐，接收时间负责判断是否赶上截止。有效事件时间缺失时回退至接收时间，保留原始 null 和降级标记。

使用 (t-W,t] 滑窗，默认 W30/S5/L2 是实验起点。每窗在 t+L 逻辑截止；调用方先提交同接收时间全部消息，再推进截止。未收到消息也能 advance 发布。迟到按目标窗口判断，不回写历史，可进入后续未关闭窗口。

water/presence 构造成从观测时间到 min(下一观测,TTL到期) 的状态段，未知/无效读数截断旧状态。flow 暂按 event_time 为统计间隔终点，区间为 (event_time-interval,event_time]；不将流量均值无限保持。有效区间裁剪到窗内，排序合并重叠后求总时长，coverage=有效并集时长/W。终态另行计算，TTL 到期即 unknown，终态未知仍可能有历史覆盖。

身份检查以 observation_id 及 device/sensor/boot/seq 为依据。完全相同重复去重，冲突拒绝。Stream 对新 boot 进行时间和质量资格检查，采用保守清空旧缓存并拒绝退役 boot。未见 boot 的真实性和新旧顺序仍需设备证据。

push 在副本上推进截止、清理历史、检查容量，全部成功后提交，保证失败不丢窗口。advance 每次最多输出 max_windows；next_end 为追赶游标，push 若需过多追赶则要求调用者分批 advance 后重试。观测缓存与退役 boot 历史分别有上限。

来源由纳入引用推导，未知中断观测也保留引用；输出经候选 AlignedWindow 验证。算法语义版本与配置摘要进入窗口身份。

## 算法与复杂度
1. 到达排序：n 条有限输入 O(n log n)。
2. 当前批处理身份检查存在逐条扫描，最坏 O(n²)，可后续以组合键字典优化。
3. 单窗逐源排序和区间合并约 O(n log n)，k 个窗口约 O(k n log n)，另加身份检查；流式每窗调用批处理还会重复身份校验，未做性能优化承诺。
4. 流式副本事务有复制开销，以简单正确性优先，不能据此宣称嵌入式或大规模适用。

## M4 的职责和输入
将有效时间段压缩为十二特征并保留缺失、来源和版本；不做情境分类或告警。输入需要窗口、不可变原始观测/有效区间与检查点，不能只用 sensor_summary。正式 DTO 不擅自扩展；先用内部实验接口验证引用完整、设备一致、窗口身份和算法配置一致。来源不可信或引用缺失必须拒绝或明确降级。

## 首轮需明确的十二项
flow_mean_lpm：有效流量时长加权均值；flow_max_lpm：有效区间峰值；flow_active_ratio：活动有效时长/总有效流量时长；flow_streak_sec：截至窗尾连续流水时长；flow_change_count：连续已知区段内活动状态变化数；water_contact：拟为窗尾状态；water_contact_sec：拟为截至窗尾连续湿时长；presence_state：窗尾状态；presence_occupied_ratio：在场有效时长/有效人员时长；presence_transition_count：连续已知区段变化数；absence_after_flow_sec：拟为流水与未检出人员连续重叠时长；data_coverage_ratio：固定权重覆盖。以上细节仍为提案，首轮必须评审并记录反例。

无有效证据的数值为 null；presence 为 unknown。missing_mask 表示本窗无可用证据，不等于窗尾 unknown。flow/presence 任一缺失则 absence_after_flow_sec=null。没有连续证据时转换数为 null；有连续证据无变化才为0。

## 每轮固定自检和交叉检查

- 交叉检查：程序对手算；离线对流式；输出对 DTO；恢复前对恢复后（对应能力实现后执行）。
- 回归：先跑当前模块，再跑受影响 M3/契约/启动检查；真实结果留 evidence，不预填通过。
- REPORT_Rxx.md 保存目标、思路、文件、命令、结果、修复、限制和下一步；未执行项写明。
- 每轮新增范围控制在一个主要能力；review 有高优先级问题先修，不带入下轮。
